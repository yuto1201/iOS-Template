# TestFlight distribution contract

`tools/distribute-testflight-build.sh` is the guarded local entry point for assigning an already processed iOS build to specified TestFlight group IDs. It accepts an absolute `--project-root`, `--issue`, `--version`, `--build-number`, and one or more distinct `--group` IDs. A failed or ambiguous attempt may be inspected and resumed with `--resume-attempt`; the tool does not resend a mutation after an unresolved intent.

The selected Issue must have a sealed `appstore.distribute_testflight` operation, a `release / strict / full` contract, configured App Store Connect Team and Bundle identities, and a matching operation preflight less than 3600 seconds old. The build must have a same-Issue #133 journal whose last processing readback is `VALID` for the same Head, version, build number, Bundle ID, and contract digest. The runner reconfirms the remote app and build before distribution. Group existence and internal/external classification come from the remote API, and each assignment succeeds only after a complete membership readback. Group creation, removal, tester management, invitations, and public links are outside this entry point.

An external group may be assigned without beta app review submission; the journal then records `not-submitted` when remote readback finds no submission. `--submit-beta-review` additionally requires an external group and `--approval 'approval: user-approval://…'` that exactly equals the live Issue operation's approval reference with `Approval required: yes`. The tool submits through `asc testflight review submit --build-id … --confirm`, then reads the beta review state. It records the observed state and never interprets submission as Apple approval.

The append-only `.artifacts/appstore-testflight/<issue>/<attempt>/` journal uses `recordType: appstore-testflight-distribution`, schema 1, event sequence, previous-event digest, sanitized group IDs, build ID, readback digests, and beta review state. It excludes group names, tester names, email addresses, invitation links, and runner output. A lock prevents concurrent attempts for the same Issue. Resume rechecks remote membership and beta review state; an intent with no confirming remote state remains unknown. The artifact and fake-runner tests do not prove live distribution.

What to Test is unavailable in this pinned adapter. In `asc` 5.4.0, `internal/cli/builds/build_test_notes.go` offers `--whats-new` as command-line text for create/update and no file or stdin input. The entry point refuses `--whats-new-locale` and `--whats-new-source` until a safe input path is established in a later Issue.
